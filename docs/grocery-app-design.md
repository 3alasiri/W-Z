# وثيقة تصميم: نظام "بقالتي الذكية" للبقالات والسوبرماركت الصغيرة

## 1. الهدف
منصة سحابية متكاملة لبقالات الأحياء: نقطة بيع، محاسبة، مخزون ومستودعات، طلب أونلاين وتوصيل، مع ذكاء اصطناعي للتنبؤ والتنبيه والطلب التلقائي من الموردين.

## 2. المستخدمون والواجهات
| الواجهة | المستخدم | المنصة |
|---|---|---|
| لوحة الإدارة | المالك/المدير/المحاسب | ويب (RTL) |
| نقطة البيع POS | الكاشير | ويب/تابلت + قارئ باركود + طابعة إيصالات |
| تطبيق المستودع | أمين المخزون | جوال (مسح بالكاميرا) |
| تطبيق العميل | سكان الحي | جوال iOS/Android + ويب |
| تطبيق المندوب | السائق | جوال |
| بوابة المورد | الموردون | ويب (استقبال وتأكيد أوامر الشراء) |

## 3. الوحدات

### 3.1 نقطة البيع
- بيع بالباركود أو البحث، منتجات بالوزن (باركود الميزان EAN-13 بادئة 2x).
- طرق دفع: نقد، مدى/بطاقة، محافظ، آجل (دفتر حساب العميل).
- مرتجعات، خصومات، عروض، إيصال ضريبي برمز QR (متوافق مع الفوترة الإلكترونية – فاتورة).
- يعمل دون اتصال ويزامن لاحقًا.

### 3.2 المحاسبة
- قيد مزدوج تلقائي لكل عملية (بيع، شراء، مرتجع، تالف، مصروف).
- دليل حسابات افتراضي، ضريبة القيمة المضافة 15% وتقرير الإقرار.
- ذمم مدينة (حسابات العملاء الآجلة) ودائنة (الموردون) مع أعمار الديون.
- إغلاق وردية وصندوق، مطابقة نقدية، تقارير: أرباح وخسائر، ميزانية، تدفق نقدي، هامش ربح لكل منتج/فئة.

### 3.3 المخزون والمستودعات
- مواقع متعددة: رف المتجر، المستودع الخلفي، فروع.
- إدخال المخزون بالباركود: مسح → جلب بيانات المنتج (قاعدة باركود داخلية/GS1) → كمية + تاريخ صلاحية + رقم دفعة.
- تتبع بالدفعة (Batch) وتطبيق FEFO (الأقرب انتهاءً يُصرف أولًا).
- جرد دوري وجرد جزئي بالمسح، تحويلات بين المواقع، تسجيل التالف والمفقود.
- تكلفة بالمتوسط المرجح.

### 3.4 الطلب الأونلاين والتوصيل
- كتالوج حي متزامن مع المخزون، سلة، جدولة موعد، استلام من المتجر أو توصيل.
- نطاق توصيل جغرافي (نصف قطر/مضلع) ورسوم حسب المسافة وحد أدنى للطلب.
- دورة الطلب: جديد → قيد التجهيز → جاهز → مع المندوب → تم التسليم / ملغى.
- شاشة تجهيز (Picking) بترتيب الممرات ومسح للتحقق، واستبدال منتج ناقص بموافقة العميل.
- تتبع المندوب لحظيًا، إثبات التسليم (صورة/رمز)، تحصيل نقدي يُقيَّد على عهدة المندوب.
- إشعارات Push/SMS/واتساب لكل مرحلة.

### 3.5 الموردون والمشتريات
- ملف المورد: المنتجات، الأسعار، مدة التوريد، الحد الأدنى للطلب، أيام التوريد.
- أوامر شراء → استلام بالمسح (مطابقة الكمية والسعر) → فاتورة مورد → قيد دائن.

## 4. الذكاء الاصطناعي والتحليلات

### 4.1 التنبؤ بالطلب
- نموذج سلاسل زمنية لكل منتج (موسمية أسبوعية، رمضان والأعياد، الرواتب، الطقس).
- يُحسب يوميًا: الطلب المتوقع، نقطة إعادة الطلب، الكمية الاقتصادية.
  - نقطة إعادة الطلب = متوسط الطلب اليومي × مدة التوريد + مخزون الأمان.
  - مخزون الأمان = Z × الانحراف المعياري للطلب × √مدة التوريد.

### 4.2 الطلب التلقائي من الموردين
1. عند نزول الكمية المتاحة (الحالي − المحجوز للطلبات + القادم) تحت نقطة إعادة الطلب.
2. تجميع الأصناف حسب المورد واقتراح الكمية (مع مراعاة الحد الأدنى وقرب انتهاء الصلاحية).
3. إنشاء مسودة أمر شراء → اعتماد المدير (أو اعتماد تلقائي دون حد مالي محدد) → إرسال للمورد عبر البوابة/البريد/واتساب.

### 4.3 تنبيهات الصلاحية
- مستويات: 30 / 14 / 7 / 3 أيام، ومنتهي.
- إجراءات مقترحة آليًا: خصم تدريجي، عرض في التطبيق للعملاء المهتمين، إرجاع للمورد، أو تسجيل تالف.
- تقرير الهدر الشهري وأثره المالي.

### 4.4 تنبيهات المخزون
- نفاد، منخفض، راكد (لا مبيعات منذ X يوم)، مخزون زائد، فروقات جرد غير طبيعية (كشف شذوذ للسرقة/الأخطاء).

### 4.5 فهم العميل وتحليل السلوك
- تقسيم العملاء (RFM): دائم، معرّض للفقد، جديد، عالي القيمة.
- سلة السوق (منتجات تُشترى معًا) لاقتراح "قد يعجبك" وترتيب الرفوف.
- توصيات شخصية في التطبيق، وتذكير "حان وقت إعادة شراء الحليب" حسب دورة شراء العميل.
- تحليلات التطبيق: مسار التصفح، التخلي عن السلة، أوقات الذروة، البحث بدون نتائج (منتجات مطلوبة غير متوفرة).
- تسعير مقترح ومراقبة هامش الربح.

### 4.6 مساعد ذكي (محادثة)
- للمدير: أسئلة بالعربية مثل "ما أكثر 10 منتجات ربحًا هذا الشهر؟" → استعلام آمن للقراءة فقط وإجابة برسم.
- للعميل: طلب بالمحادثة/الصوت "أبغى خبز وحليب وبيض" → سلة جاهزة.

## 5. المعمارية التقنية
```
تطبيقات (Flutter للجوال، Next.js للويب)
        │ HTTPS / WebSocket
بوابة API (REST + Realtime)
        │
خدمات: POS | المحاسبة | المخزون | الطلبات | التوصيل | المشتريات | الإشعارات
        │                         │
PostgreSQL (Supabase) + RLS      خدمة الذكاء الاصطناعي (Python: تنبؤ، توصيات، شذوذ)
        │                         │
تخزين ملفات | طوابير مهام مجدولة (cron) | نموذج لغوي للمساعد
```
- تعدد المستأجرين: كل متجر `store_id` مع سياسات RLS.
- العمل دون اتصال في POS عبر قاعدة محلية (SQLite) ومزامنة.
- الخرائط والتتبع: Google Maps / Mapbox. الدفع: بوابة محلية (مدى، Apple Pay).

## 6. نموذج البيانات (الجداول الأساسية)
- `stores`, `users`, `roles`
- `products` (barcode, name, category_id, unit, price, cost, vat_rate, min_qty)
- `product_batches` (product_id, location_id, qty, expiry_date, cost)
- `locations`, `stock_movements` (type: sale/purchase/transfer/adjust/waste)
- `customers`, `customer_addresses`, `customer_events` (تحليلات السلوك)
- `orders`, `order_items`, `deliveries`, `drivers`
- `suppliers`, `supplier_products`, `purchase_orders`, `po_items`, `goods_receipts`
- `accounts`, `journal_entries`, `journal_lines`, `invoices`, `payments`
- `forecasts` (product_id, date, predicted_qty, reorder_point)
- `alerts` (type, severity, entity, status)

## 7. الشاشات الرئيسية
1. لوحة القيادة: مبيعات اليوم، الربح، الطلبات النشطة، التنبيهات، توصيات الذكاء الاصطناعي.
2. نقطة البيع.
3. المنتجات والمخزون (مع فلتر الصلاحية).
4. الاستلام بالباركود.
5. الطلبات (لوحة كانبان) + خريطة المندوبين.
6. المشتريات والموردون (مسودات الطلب التلقائي).
7. المحاسبة والتقارير.
8. العملاء والتحليلات.
9. الإعدادات (الضريبة، التوصيل، الصلاحيات، حدود الاعتماد).

## 8. الأمان والصلاحيات
- أدوار: مالك، مدير، محاسب، كاشير، أمين مخزون، مندوب.
- سجل تدقيق لكل تعديل سعر/مخزون/قيد.
- تشفير البيانات، مصادقة ثنائية للمدير، الامتثال لنظام حماية البيانات الشخصية (PDPL) وموافقة العميل على التحليلات.

## 10. مؤشرات النجاح
- خفض الهدر بسبب الصلاحية ≥ 30%.
- خفض حالات النفاد ≥ 40%.
- زمن تجهيز الطلب < 10 دقائق، والتوصيل < 45 دقيقة.
- دقة الجرد ≥ 98%.
