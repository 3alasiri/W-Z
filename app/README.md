# بقالتي الذكية

نظام لإدارة البقالات: المنتجات، المخزون بالباركود والدفعات وتواريخ الصلاحية، نقطة البيع، والتنبيهات.

## التشغيل
```bash
cd app
cp .env.example .env.local   # بيانات مشروع Supabase
npm install
npm run dev                  # http://localhost:3000
```

## الموجود في المرحلة 1
- تسجيل الدخول وإنشاء متجر (عدة متاجر ومستخدمين مع صلاحيات: مالك، مدير، كاشير، أمين مخزون).
- المنتجات: تعريف بالباركود، الفئات، الموردون، التكلفة والسعر.
- استلام البضاعة بالباركود (قارئ USB أو الكاميرا) مع الكمية وتاريخ الصلاحية والموقع، كل استلام دفعة مستقلة، وتحديث التكلفة بالمتوسط المرجح.
- نقطة البيع: خصم ذري بالأقرب انتهاءً أولًا (FEFO)، يمنع بيع المنتهي والبيع فوق المتوفر، ضريبة 15٪ شاملة، إيصال قابل للطباعة.
- التنبيهات: نفاد، انخفاض تحت نقطة إعادة الطلب المحسوبة، قرب الانتهاء، منتهي مع تسجيله تالفًا.
- لوحة القيادة وسجل المبيعات.

## قاعدة البيانات
الترحيلات في `supabase/migrations`. كل الجداول محمية بـ RLS حسب المتجر، والعمليات الحساسة (البيع، الاستلام، التسوية) تتم عبر دوال تتحقق من الصلاحية.

## الموجود في المرحلة 2
- **المحاسبة:** دليل حسابات افتراضي، وقيد مزدوج تلقائي لكل بيع واستلام وتالف وتسوية وسداد ومصروف، وقائمة الدخل، وإقرار ضريبة القيمة المضافة، وميزان المراجعة، وسجل القيود.
- **العملاء الآجلون:** البيع الآجل من نقطة البيع مع حد ائتمان، والتحصيل، والأرصدة.
- **الموردون:** الأرصدة المستحقة، والسداد نقدًا أو بنكيًا، ورقم الجوال لإرسال الأوامر عبر واتساب.
- **أوامر الشراء:** يجهّزها النظام كل ساعة (pg_cron) لكل مورد عند نزول الكمية تحت نقطة إعادة الطلب، وتُعتمد تلقائيًا تحت حد يحدده المالك، ثم تُرسل وتُستلم كليًا أو جزئيًا مع تاريخ الصلاحية.

التكاليف في النظام قبل الضريبة، وأسعار البيع شاملة الضريبة.

## الموجود في المرحلة 3
- **متجر العميل** `/shop/<رابط-المتجر>`: كتالوج حي بالكميات المتاحة، وسلة محفوظة، وطلب توصيل أو استلام، وتحديد الموقع، والدفع عند الاستلام نقدًا أو مدى، وتتبع الطلب لحظيًا مع بُعد المندوب.
- **لوحة الطلبات** `/orders`: أعمدة حسب الحالة، تتحدث فورًا مع تنبيه صوتي للطلب الجديد. التجهيز بمسح الباركود، وتعليم غير المتوفر، وتعيين المندوب.
- **تطبيق المندوب** `/driver`: طلباته فقط، والملاحة والاتصال، ومشاركة الموقع أثناء التوصيل، وتأكيد التسليم، والنقد الذي معه.
- **الفريق والإعدادات**: إضافة أعضاء بأدوار (مدير، كاشير، أمين مخزون، مندوب)، ورابط المتجر ورسوم التوصيل ونطاقه والحد الأدنى.
- الكمية المطلوبة أونلاين تُحجز حتى التسليم، وعند التسليم يتحول الطلب لفاتورة وقيد (رسوم التوصيل في حساب 4200).

## الموجود في المرحلة 4: الذكاء الاصطناعي والتحليلات
- **توقع الطلب** لكل صنف للأيام السبعة القادمة: متوسط يوم الأسبوع (حتى 8 أسابيع) ممزوجًا بالمتوسط اليومي ومعامل اتجاه آخر أسبوعين. أوامر الشراء التلقائية تحسب الكمية من هذا التوقع.
- **عروض ذكية ضد الهدر**: يقدّر النظام ما سيُباع قبل انتهاء الصلاحية ويقترح خصمًا 15 أو 25 أو 40٪، يُطبَّق بضغطة على نقطة البيع والمتجر الأونلاين معًا.
- **تحليلات** `/insights`: أصناف ستنفد قبل التوريد، أصناف راكدة، تصنيف ABC، ربح كل صنف، شرائح العملاء مع رابط تواصل واتساب، منتجات تُشترى معًا، أوقات الذروة، وما بحث عنه العملاء ولم يجدوه.
- **توصيات في متجر العميل**: إعادة الشراء حسب دورة العميل، ومنتجات تُشترى مع ما في السلة، والأكثر طلبًا.
- **المساعد الذكي** `/assistant`: محادثة بالعربية تجيب من لقطة لبيانات المتجر عبر Claude API. يتطلب المتغير `ANTHROPIC_API_KEY` على الخادم.

## إضافات بعد المراحل الأربع
- **بيانات تجريبية**: زر في لوحة القيادة لمتجر فارغ يضيف 25 منتجًا و4 موردين و8 عملاء ومبيعات 6 أسابيع مع قيود محاسبية متوازنة.
- **الفوترة الإلكترونية (المرحلة الأولى)**: رمز QR بصيغة TLV (اسم البائع، الرقم الضريبي، الوقت، الإجمالي، الضريبة) على إيصال نقطة البيع وصفحة الفاتورة `/sales/<id>`. يتطلب إدخال الرقم الضريبي في الإعدادات. الربط المباشر بمنصة فاتورة (المرحلة الثانية) يحتاج تسجيل المنشأة لدى الهيئة.
- **خريطة التتبع**: المتجر والعميل والمندوب على خريطة OpenStreetMap في صفحة تتبع العميل وصفحة الطلب.
- **الدفع الإلكتروني المسبق** عبر Moyasar (مدى، Apple Pay، بطاقات): يُنشئ الخادم فاتورة دفع، ويتحقق من حالتها ومبلغها لدى Moyasar قبل اعتماد الطلب. لا يُجهَّز الطلب قبل الدفع، ويُلغى تلقائيًا إن لم يُدفع خلال 30 دقيقة.
  - **مهم**: لم يُختبر مع Moyasar فعليًا. جرّبه بمفاتيح الاختبار (`sk_test_...`) قبل التشغيل.
  - اضبط رابط الإشعارات في لوحة Moyasar على `https://<موقعك>/api/pay/webhook`.

## النشر على Vercel
1. في Vercel: **Add New Project** ← اختر المستودع ← **Root Directory**: `app`.
2. أضف متغيرات البيئة من `.env.example`: `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` (إلزامية)، و`ANTHROPIC_API_KEY` للمساعد الذكي، و`MOYASAR_SECRET_KEY` و`SUPABASE_SERVICE_ROLE_KEY` و`NEXT_PUBLIC_SITE_URL` للدفع.
3. **Deploy**.
4. في Supabase: **Authentication ← URL Configuration**: ضع رابط Vercel في **Site URL** وأضفه إلى **Redirect URLs** (لروابط تأكيد البريد).
5. سجّل حسابًا، أنشئ متجرك، ثم اضغط "تعبئة المتجر ببيانات تجريبية" للتجربة.
